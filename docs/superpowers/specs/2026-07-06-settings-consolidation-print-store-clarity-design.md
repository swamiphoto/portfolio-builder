# Design: Settings consolidation + print-store clarity (launch polish)

Generated by /brainstorming on 2026-07-06
Status: APPROVED — Workstream A of "close the loop for launch"

## Framing

Pre-launch polish of the **Site Settings** popover (`components/admin/platform/SiteSettingsPopover.js`) so a photographer can set up selling prints without confusion. Two workstreams were split out; this spec is **A (settings UX)**. **B (real print-order go-live: Phase 2 fulfillment merge + Prodigi account + Stripe/Prodigi live-vs-sandbox)** is scoped separately after A.

## Key finding

`clientDefaults.defaultCurrency`, `defaultWatermarkUrl`, and `paymentsEnabled` are written by the "Payments" drill-in but **read by nothing** (grep-confirmed; the real watermark is a separate per-page `downloads.watermarkEnabled` toggle). The "Payments" panel is dead UI overlapping the print store's real Stripe Connect. So it is removed, not migrated.

## Changes

### 1. Remove the "Payments" section
- Delete the `payments` drill row (main view) and the `if (view === 'payments')` panel.
- Leave the orphaned `clientDefaults` fields in the siteConfig schema (harmless; removing schema is out of scope).
- **Print store becomes the single selling section.**

### 2. Custom-domain row (main view) — stable label, domain as secondary
Replace the row that uses the domain name as its title:
- No domain → label `Set up custom domain` (unchanged).
- Connected → label **`Custom domain`**, hint `<name> — Connected`.
- Pending → label **`Custom domain`**, hint `<name> — Action needed`.

Keeps the label a noun consistent with sibling rows; the domain is viewed/edited/removed inside the drill-in (DomainPanel, unchanged).

### 3. Print store panel — clarity, grouping, reveal-on-enable
Rewrite `PrintView`. When the store is **off**: show only the intro line + the enable toggle. When **on**: reveal grouped controls.

- **Intro** (muted, one line): "Sell prints of your photos. We print and ship worldwide — you set the markup and keep the difference."
- **Enable print store** — toggle (top, always visible).
- **PRICING** group (revealed when enabled):
  - **Your markup** — number input (× lab cost), min 1, step 0.1, default 3.
  - **Live example** under the input, recomputed from the current markup value using an illustrative $20 lab cost: `You charge {m}× our lab cost. A print that costs $20 to make sells for ${20*m} — you keep ${20*m - 20}.`
  - **Show starting price on photos** — toggle, helper: "Displays 'From $X' on photos that are for sale."
- Divider.
- **PAYOUTS** group (revealed when enabled):
  - Own labeled section (no longer inline with the price toggle).
  - Not connected → **Connect payouts** button, helper: "Get paid through Stripe. Required before you can sell."
  - Connected → **Connected ✓** (green), helper: "Earnings go to your Stripe account."
  - Connect flow + status fetch unchanged (`/api/admin/print/connect`, `/connect/status`).

### 4. Popover height / no scroll
`PopoverShell` caps `maxHeight` at a hard `Math.min(680, availableSpace)`. Raise the cap so the popover fits the viewport (use the available-space calc without the 680 ceiling, keeping the existing bottom/top margins so it never touches an edge). Both the `openUp` and `below` branches. Combined with removing the Payments row + reveal-on-enable, the main view no longer scrolls on a normal screen; it still caps to the viewport on short screens (scroll only when genuinely taller than the screen).

## Out of scope
- Any change to DomainPanel internals, the print checkout/fulfillment, or the siteConfig schema.
- Workstream B (print-order go-live).

## Verification
- Visual: main settings view fits without a scrollbar on a standard laptop viewport; print store panel reveals grouped controls with live markup example; payouts in its own section; domain row shows `Custom domain` + `swami108.com — Connected`.
- No console errors; existing settings still save (autosave debounce unchanged).
- `npm test` stays green (these are presentational; the `subdomainHost` test from the domain branch remains).
