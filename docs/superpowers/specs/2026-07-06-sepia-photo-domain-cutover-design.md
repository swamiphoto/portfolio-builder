# Design / Runbook: `sepia.so` → `sepia.photo` domain cutover

Generated by /brainstorming on 2026-07-06
Status: APPROVED — executing

## Framing

Pre-launch platform-domain swap from `sepia.so` to `sepia.photo`. Both are owned
on Namecheap. There are no real users yet (only `swamiphoto` / test accounts), so
this is a **config/infra cutover plus a tiny optional code cleanup** — no data
migration, no mandatory redirects. It is the domain half of the print-store
go-live dependency (design §10), done independently of the print store itself.

The code is already domain-agnostic: all functional URL logic derives from the
`NEXT_PUBLIC_ROOT_DOMAIN` env var (`common/domainUtils.js` — `siteUrlFor`,
`parseHost`, `basePathFor`), and Stripe Connect onboarding URLs derive from
`req.headers.origin`/`host` (`pages/api/admin/print/connect.js:28`). Flipping the
env var flips every real URL. The UI even already displays `{username}.sepia.photo`
in several places.

## Not in scope

- Registering **production** Stripe/Prodigi webhook endpoints or flipping live
  payment keys — that is print-store go-live (Phase 3), separate.
- Any user-data migration or `sepia.so` link preservation — pre-launch, nothing
  to preserve.

## Decisions

- **www is primary** (`www.sepia.photo`), apex `sepia.photo` 308-redirects to www
  — mirrors the `sepia.so` layout.
- **DNS: delegate `sepia.photo` nameservers to Vercel** so Vercel manages DNS and
  **auto-issues the `*.sepia.photo` wildcard TLS cert**. This is the clean escape
  from the `sepia.so` per-subdomain cert workaround (Vercel cannot DNS-01 a
  wildcard while DNS is external at Namecheap). No email/other DNS on `sepia.photo`
  today; if added later, manage it in Vercel.
- **Keep `sepia.so` as a 308 redirect** to `www.sepia.photo` (cheap insurance);
  its env and config are left intact until the new domain is verified good.

## Cutover runbook (ordered — order prevents an auth/SSL gap)

**The critical gotcha:** `NEXT_PUBLIC_ROOT_DOMAIN` is a `NEXT_PUBLIC_` var, so it
is **baked into the build at compile time**. Changing it requires a *fresh
production build*, then a **promote** to switch the `www` alias — not just an env
set (matches the redeploy-needs-promote history). Do the env flip + fresh build +
promote as the **final** step, after `sepia.photo` serves HTTPS.

## Code cleanup (optional, non-blocking)

The cutover works without this — the three strings already display `sepia.photo`,
which is the target. But they are hardcoded, so in local dev they wrongly show
`sepia.photo` instead of `lvh.me`. Replace with the env-derived root domain:

- `components/admin/platform/AdminLayout.js:156` — `{username}.sepia.photo`
- `components/admin/platform/PlatformSidebar.js:745` — `{username}.sepia.photo`
- `components/admin/platform/SiteSettingsPopover.js:479` — `${previewSubdomain}.sepia.photo`

Add a tiny client helper `displayRootDomain()` = `(process.env.NEXT_PUBLIC_ROOT_DOMAIN || 'localhost:3000').replace(/:\d+$/, '')`,
TDD it, and use it in those three spots. Landing-page marketing examples
(`components/landing/Landing.js`) stay as brand copy.

## Risks & rollback

- **`NEXT_PUBLIC_` baked at build time** → must do a fresh build after the env
  change; a bare env set on the old build has no effect. Promote only after the
  new build succeeds.
- **Cookie domain change** invalidates any `sepia.so` sessions → fresh logins.
  Fine pre-launch.
- **NS propagation delay** (minutes–hours) before certs issue → do NS first,
  verify delegation + cert before promoting the `www` cutover.
- **Google OAuth redirect URI** is the one thing that silently breaks sign-in if
  forgotten — step 7 is mandatory before declaring done.
- **Rollback is trivial:** `sepia.so`, its domains, and its env are left intact
  until the new domain is verified good; if anything is wrong, we simply don't
  promote / re-promote the last good `sepia.so` build.

## Verification incident reference

If prod auth 500s after the cutover with "There is a problem with the server
configuration," check the production env still has all app secrets
(`NEXTAUTH_SECRET`, `GOOGLE_CLIENT_*`, `R2_*`, etc.) — Vercel bakes env at build
time and an emptied env has bitten this project before.
